# WorldMind — 재구축 요청 스펙

AI 기반 창작 세계관 마인드맵 웹앱을 **단일 HTML 파일**로 만들어주세요.
기존 버전이 동작 중이며, **기존 데이터를 그대로 읽어야 합니다.** 아래 스키마와 저장 키는 반드시 그대로 유지해주세요.

---

## 0. 기술 제약 (필수 준수)

- **단일 `.html` 파일** — HTML + CSS + JS를 한 파일에 인라인. 빌드 도구·번들러 없음
- 외부 의존성은 CDN 2개만:
  - Google Fonts: `Cinzel` (400/600/700), `Noto+Sans+KR` (300/400/500/700)
  - Firebase JS SDK **compat** 10.12.2 (`firebase-app-compat.js`, `firebase-database-compat.js`)
- 프레임워크 없음 (React/Vue 사용 금지). Vanilla JS + 직접 DOM 조작
- 연결선은 인라인 SVG 레이어로 그림
- UI 언어는 **한국어**

## 1. 데이터 스키마 (변경 금지 — 기존 DB 호환)

### 1-1. 최상위 구조

```js
tabs = [ Tab, Tab, ... ]     // 전역 배열
activeTabId = "i1234..."     // 현재 선택된 탭 id
```

### 1-2. Tab

```js
{
  id: "i1738..",           // gid()로 생성
  title: "세계관 이름",
  nodes: [ Node, ... ],
  edges: [ Edge, ... ],
  events: [ Event, ... ],
  worldPrompt: "",         // 세계관 설정 자유 텍스트
  refImages: []            // 참고 이미지 base64 배열 (최대 3장, 로컬 전용·Firebase 미동기화)
}
```

### 1-3. Node

```js
{
  id: "i1738..",
  type: "world"|"group"|"space"|"char"|"item"|"trait"|"custom",
  name: "노드 이름",
  desc: "설명",
  x: 2000,                 // 캔버스 절대 좌표 (px)
  y: 2000,
  _exp: false,             // 설명 펼침 상태 (런타임 전용, 저장 안 함)
  _aiPreview: false        // AI 미리보기 노드 표시 (런타임 전용, 저장 안 함)
}
```

### 1-4. Edge

```js
{
  id: "i1738..",
  from: "노드id",
  to: "노드id",
  label: "관계명",          // 4자 이내 짧은 라벨
  desc: "관계 상세 설명",
  isParent: false          // true면 부모-자식(계층) 관계, false면 일반 관계
}
```

### 1-5. Event (사건)

```js
{
  id: "i1738..",
  time: "1년 전",           // 자유 형식 시간 표현
  body: "사건 내용",
  order: 10                // 정수, 낮을수록 과거
}
```

### 1-6. ID 생성

```js
let idC = Date.now();
const gid = () => 'i' + (idC++);
```

### 1-7. 노드 타입 상수 (그대로 유지)

```js
const TL = {world:'세계', group:'집단', space:'공간', char:'인물', item:'사물', trait:'성격', custom:'기타'};
const TI = {world:'🌍', group:'👥', space:'🗺', char:'👤', item:'⚔️', trait:'💎', custom:'📌'};
const TC = {world:'#9b59d6', group:'#4a9edd', space:'#3ecfb8', char:'#6bbd4a', item:'#e8b84b', trait:'#d4914a', custom:'#5a6090'};
```

### 1-8. 하위 호환 함수

기존 데이터에 누락 필드가 있을 수 있으므로 로드 시 반드시 통과시켜주세요:

```js
function sanitizeTab(t){
  if(!t.nodes) t.nodes = [];
  if(!t.edges) t.edges = [];
  if(!t.events) t.events = [];
  if(!t.refImages) t.refImages = [];
  return t;
}
```

## 2. 저장소 (키 변경 금지)

### 2-1. localStorage

| 키 | 내용 |
|---|---|
| `wm_tabs` | `JSON.stringify({tabs})` — 전체 탭 데이터 |
| `wm_k` | Anthropic API 키 |
| `wm_gk` | Google API 키 (이미지 생성용) |
| `wm_mh` | 마스터 코드의 SHA-256 해시 |
| `wm_fbcfg` | Firebase 설정 원문 문자열 |

### 2-2. Firebase Realtime Database 구조

루트: `worldmind`

```
worldmind/
  tabList: [ {id, title}, ... ]           // 탭 순서·목록
  tabs/
    {tabId}/
      meta:   {title, worldPrompt, _w}
      nodes/
        {nodeId}: {type, name, desc, x, y, _w}
      edges/
        {edgeId}: {from, to, label, desc, isParent, _w}
      events/
        {eventId}: {time, body, order, _w}
```

- `_w`는 쓴 세션의 ID. 자기 쓰기 에코를 무시하는 데 사용
- 세션 ID 생성: `const FB_SID = 's' + Date.now().toString(36) + Math.random().toString(36).slice(2,6);`

### 2-3. 구 포맷 자동 마이그레이션 (필수)

기존에 `worldmind/{tabs: [...]}` (배열 통째) 형식으로 저장된 데이터가 존재합니다.
초기화 시 루트를 한 번 읽어서 `data.tabs`가 배열이면, 위의 항목별 경로 구조로 변환 후 재기록해주세요. 변환 전 데이터는 손실 없이 옮겨져야 합니다.

## 3. 실시간 동기화 요구사항

여러 사용자가 동시에 편집합니다. 전체 덮어쓰기 방식은 사용하면 안 됩니다.

- **쓰기**: 변경된 개별 노드/엣지/사건만 해당 경로에 `set()`. 이전 스냅샷과 diff를 떠서 바뀐 항목만 전송
- **읽기**: `child_added` / `child_changed` / `child_removed` 리스너로 항목 단위 수신
- **에코 방지**: 수신한 데이터의 `_w === FB_SID`면 무시
- **탭 전환 시**: 이전 탭 리스너를 모두 해제하고 새 탭에 재부착
- **탭 목록**: `tabList`에 `value` 리스너를 걸어 다른 사용자의 탭 추가/삭제를 감지
- **원격 수신 렌더링**: 연속 수신 시 50ms 디바운스로 묶어서 렌더

상태 표시: 탑바에 점 + 텍스트 (`실시간 동기화` / `연결 중…` / `연결 오류` / `오프라인`)

### Firebase 설정 파서

사용자가 설정을 붙여넣는 형식이 다양합니다. 아래 3가지를 모두 파싱해주세요:
- 순수 JSON
- JS 객체 리터럴 (키에 따옴표 없음)
- `const firebaseConfig = { ... };` 전체 선언문

## 5. 기능 명세

### 5-1. 탭 (세계관 프로젝트)

- 여러 세계관을 탭으로 분리 관리
- **＋ 추가** — 새 탭 생성 (기본 `world` 타입 노드 1개 자동 생성)
- **⧉ 복제** — 현재 탭의 모든 노드·엣지·사건을 딥카피. 모든 ID를 새로 발급하고 엣지의 from/to를 새 ID로 리맵. 제목은 `복사_원본이름`
  - ⚠️ 복제 후 Firebase 저장 시 diff 스냅샷을 반드시 비워야 함 (안 그러면 "변경 없음"으로 판단해 아무것도 기록되지 않음)
- **✕ 삭제** — 확인 모달 후 삭제. 마지막 탭은 삭제 불가
- 편집 모드에서만 추가/삭제/복제 가능

### 5-2. 노드

- 타입 7종 (§1-7). 타입별 색상·아이콘·테두리
- **클릭** — 설명 펼침/접기 + 선택
  - ⚠️ 드래그로 이동 후 마우스를 놓을 때는 설명이 펼쳐지지 않아야 함 (전역 `_justDragged` 플래그로 클릭 억제)
- **드래그** — 위치 이동 (편집 모드 전용). 3px 이상 움직여야 드래그로 판정
- **우클릭 / 0.5초 롱프레스** — 컨텍스트 메뉴
  - 롱프레스는 태블릿 지원용. 10px 이상 움직이면 취소
  - 롱프레스 발동 시 진행 중인 드래그를 강제 해제해야 함 (합성 `mouseup` 디스패치)
  - ⚠️ 롱프레스가 document에 등록하는 리스너는 재렌더 시 반드시 정리해야 함 (누수 → 심각한 성능 저하)
- 컨텍스트 메뉴 항목: `노드 편집` `관계 추가` `주인공 방문` / `현재 노드 추천` `하위 노드 AI 추천` / `삭제`
- 노드 삭제 시 연결된 엣지도 함께 삭제. 자식 노드 처리 방식 선택 제공

### 5-3. 연결선 (관계)

- 두 종류: **부모-자식** (`isParent: true`, 실선) / **일반 관계** (점선)
- 라벨을 선 중앙에 표시. 긴 텍스트는 CJK 줄바꿈 처리
- 클릭으로 선택, 우클릭/롱프레스로 메뉴 (`관계 편집` `관계 AI 추천` `삭제`)
- 관계 추가: 노드 메뉴에서 시작 → 배너 표시 → 대상 노드 클릭. ESC로 취소

### 5-4. 노드 자동 정렬 (🔀)

부모-자식 관계만 사용하는 **방사형 트리 레이아웃**. 일반 관계는 배치에 영향 없음.

- 루트 노드가 중심, 자식이 동심원으로 바깥 확장
- 자식이 많은 가지에 더 넓은 각도 배분 (리프 노드 수 기반 가중치)
- 트리가 여러 개면 원을 트리별로 분할
- 부모 없는 고립 노드는 최외곽 링에 균등 배치
- 겹침 제거: Force Repulsion 반복 (최소 간격 220px)
- 노드가 늘어나면 좌우가 아닌 **전 방향으로 원형 확장**
- 실행 전 확인 모달. 0.5초 트랜지션 애니메이션 후 자동 줌핏
- 편집 모드 전용

### 5-5. 세계관 패널 (🌐)

- `worldPrompt` 자유 텍스트 입력 + 저장
- 참고 그림체 이미지 최대 3장 업로드 (base64, 로컬 전용)

### 5-6. 대화 패널 (💬)

- 세계관에 대해 AI와 자유 질의응답
- 시스템 프롬프트에 `worldPrompt` + 전체 노드 목록 + 전체 관계 목록 주입
- 멀티턴 히스토리 유지

### 5-7. 사건 패널 (📜)

- 사건 목록을 `order` 순으로 표시
- **AI 사건 생성** — 세계관·노드·관계·기존 사건을 참고해 새 사건 1개 생성. `order`로 시간 순서상 위치 지정
- 사건 추가/편집/삭제

### 5-8. 주인공 방문 (🧭)

- 노드 메뉴에서 실행. 해당 노드에 주인공이 상호작용하는 장면을 2~3문단으로 서술
- 대상 타입에 따라: 장소=방문 / 인물=대화 / 사물=획득·관찰 / 사건=체험
- 연결된 노드를 함께 등장시킴
- **다시 추천** / **이미지 생성** / **사건으로 저장** 버튼

### 5-9. AI 노드 생성 (✨)

프롬프트 한 줄로 노드+관계를 한번에 생성.

플로우:
1. 버튼 → 프롬프트 입력 모달
2. `생성하기` → 모달 닫히고 캔버스에 반투명 로딩 오버레이
3. 생성 완료 → 새 노드들이 **굵은 글씨 + 펄스 애니메이션**으로 캔버스에 직접 배치 (설명 펼친 상태). 엣지도 강조
4. 우측 하단 플로팅 패널: 새 노드 수 / 새 관계 수 + `추가하기` `↻다시 생성` `닫기`
5. `추가하기` → 미리보기 플래그 제거하고 영구 저장
   `다시 생성` → 미리보기 제거 후 같은 프롬프트로 재시도
   `닫기` → 미리보기 전부 제거, 원상 복원

요구사항:
- 프롬프트에 등장하는 **모든 주요 명사**(인물·장소·사물·집단)를 노드로 생성
- 기존 노드가 있으면 이름으로 매칭해 새 노드와 관계 연결
- 격자 배치 + 약간의 랜덤 오프셋

### 5-10. AI 추천 (노드 / 관계)

- **현재 노드 추천** — 선택 노드를 개선한 3가지 버전 제시
- **하위 노드 추천** — 자식으로 추가할 노드 3가지 제시
- **관계 추천** — 두 노드 사이에 어울리는 관계 3가지 제시
- 카드 형태로 표시, 클릭하면 적용. `↻ 다시 추천` 지원

### 5-11. 편집 모드 / 보기 전용

- 기본은 **보기 전용**. 마스터 코드 입력 시 편집 모드 전환
- 마스터 코드는 SHA-256 해시로 `wm_mh`에 저장 (평문 저장 금지)
- 설정에서 마스터 코드 변경 가능

| 동작 | 보기 전용 | 편집 모드 |
|---|---|---|
| 노드/관계 추가·수정·삭제 | ❌ | ✅ |
| 노드 드래그 이동 | ❌ | ✅ |
| 탭 추가·삭제·복제 | ❌ | ✅ |
| 노드 정렬 | ❌ | ✅ |
| 노드 클릭·설명 펼치기 | ✅ | ✅ |
| 캔버스 팬·줌 | ✅ | ✅ |
| AI 대화·추천 조회 | ✅ | ✅ |

⚠️ 편집 모드로 전환될 때 노드를 다시 렌더해야 드래그 핸들러가 부착됩니다.

### 5-12. 저장 / 로드

- **💾 저장** — 전체 탭 데이터를 `worldmind-export.json`으로 다운로드
- **📂 로드** — `.json` 파일 선택 → 확인 모달 (파일명 + 탭/노드/관계/사건 개수 미리보기, "모든 내용을 덮어씁니다" 경고) → 확정 시 전체 교체 + Firebase 동기화 + 줌핏

### 5-13. 설정 (⚙)

- Anthropic API 키
- Google API 키 (이미지 생성용)
- Firebase 설정 (붙여넣기)
- 마스터 코드 변경

## 6. AI 통합

### 6-1. 텍스트 생성 — Anthropic API

- 모델: `claude-opus-4-6` (상수 하나로 관리해 한 곳에서 교체 가능하게)
- 엔드포인트: `https://api.anthropic.com/v1/messages`
- 헤더에 `anthropic-dangerous-direct-browser-access: true` 필요
- 사용처 6곳: 대화 패널 / 사건 생성 / 노드 추천 / 관계 추천 / 주인공 방문 / AI 노드 생성

### 6-2. 이미지 생성 — Google Gemini

- 모델: `gemini-3.1-flash-image-preview`
- `generationConfig: { responseModalities: ['IMAGE','TEXT'] }`
- 사용처: 주인공 방문 장면 일러스트

### 6-3. JSON 파싱 (중요)

AI가 JSON 앞뒤에 설명 텍스트나 마크다운 코드펜스를 붙이는 경우가 많고, 토큰 한계로 잘리기도 합니다. **정규식 기반 추출은 실패합니다.** 아래 3단 방어를 구현해주세요:

1. **브래킷 카운팅 추출** — 문자열 내부의 `{}`/`[]`/이스케이프를 인식하며 깊이를 세서 첫 번째 완전한 블록만 정확히 잘라냄. 객체용(`{...}`)과 배열용(`[...]`) 각각 필요
2. **직접 파싱 우선** — `JSON.parse(원본)`을 먼저 시도. 실패할 때만 복구 함수를 통과시킴 (복구 함수를 무조건 거치면 정상 JSON이 오히려 깨짐)
3. **부분 복구** — 그래도 실패하면 배열 안의 개별 객체를 하나씩 브래킷 카운팅으로 추출해서 정상인 것만 수집

복구 함수는 미닫힌 따옴표·잘린 문자열·불완전한 마지막 객체·누락된 닫는 괄호를 처리해야 합니다.

### 6-4. AI 프롬프트 공통 규칙

- **주인공 방문**과 **사건 생성**은 반드시 **현재 존재하는 노드의 이름만** 사용해야 합니다. 새로운 인물·장소·사물·집단을 만들어내면 안 됩니다. 시스템 프롬프트와 유저 프롬프트 양쪽에 사용 가능한 이름 목록을 전달하고 명시적으로 제약을 거세요
- 컨텍스트 빌더 함수를 두고 노드 목록 / 관계 목록 / 사건 목록을 문자열로 만들어 재사용

## 8. 성능 요구사항

노드가 수십 개로 늘고 탭을 오래 전환하면 심하게 느려지는 문제가 있었습니다. 아래를 준수해주세요:

1. **document 레벨 리스너 누수 금지** — 노드마다 등록하는 리스너(특히 롱프레스의 `mousemove`)는 재렌더 시 전부 해제. 클린업 배열로 추적
2. **이중 렌더 금지** — 한 번의 렌더 사이클에서 연결선을 두 번 그리지 않도록
3. **원격 업데이트 디바운스** — Firebase 수신이 연속될 때 50ms로 묶어 한 번만 렌더
4. 자동 저장은 localStorage만 주기 실행. Firebase는 변경 발생 시 즉시 diff 전송
